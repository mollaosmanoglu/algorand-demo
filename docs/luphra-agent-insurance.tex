\section{Context and Scope}

Luphra MicroCover is a hackathon demonstration of per-action insurance for
autonomous AI agents. An agent requests coverage before performing an economic
action, receives a quote, pays a small premium through x402 on Algorand, and
receives a coverage receipt.

The initial demonstration covers one scenario: a procurement agent buying API
credits from a new vendor. It is intended to prove the payment and coverage
workflow, not to provide a production insurance product.

\subsection{Problem}

AI agents can spend money, call tools, communicate with third parties, and make
decisions on behalf of users. Existing controls generally allow or deny an
action. They do not attach dynamically priced financial protection to an
individual action.

Traditional insurance premiums are also poorly matched to agent activity. The
risk can vary with the transaction amount, vendor, requested action, user
policy, model confidence, and execution context.

\section{Goals and Non-Goals}

\subsection{Goals}

\begin{itemize}[leftmargin=*]
  \item Observe multiple Codex agents and stream their activity into one
  dashboard.
  \item Display an agent sidebar, central live activity stream, agent summary,
  and settlement panel.
  \item Evaluate a selected existing tool call before it executes.
  \item Allow harmless actions, deny unacceptable actions, and dynamically
  price coverage for allowed consequential actions.
  \item Collect the quoted premium through x402 using Algorand TestNet USDC.
  \item Block covered Codex tool calls until the quoted coverage flow has been
  completed.
  \item Return and display a coverage receipt containing the quote and coverage
  terms, with a settlement reference when the middleware exposes one.
  \item Record the tool outcome and publish it to the live dashboard.
  \item Keep the implementation small enough to explain and demonstrate live.
\end{itemize}

\subsection{Non-Goals}

\begin{itemize}[leftmargin=*]
  \item Production insurance underwriting, licensing, or claims administration.
  \item MainNet payments or real customer funds.
  \item Building a custom facilitator or operating an Algorand node.
  \item Deploying an AVM smart contract.
  \item Supporting EVM, Solana, subscriptions, or fiat checkout.
  \item Building custom business tools or an MCP proxy.
  \item Intercepting every Codex built-in tool or arbitrary network request.
  \item Building a production customer, policy-management, or claims dashboard.
\end{itemize}

\subsection{Component Responsibilities}

\begin{tabularx}{\textwidth}{@{}lX@{}}
\toprule
\textbf{Component} & \textbf{Responsibility} \\
\midrule
Agent &
Selects and calls an existing tool normally. \\
App Server &
Emits continuous thread, turn, item, command, MCP, and status events. It
provides observability but does not price risk or enforce coverage. \\
Hook &
Receives \texttt{PreToolUse}, submits the pending tool name and arguments for
coverage, allows harmless calls, blocks denied or covered calls that still need
payment, and records harmless-call outcomes through \texttt{PostToolUse}. The
current hook does not sign or submit x402 payments itself. \\
Backend &
Prices the proposed action, hosts the x402-protected coverage resource, returns
coverage receipts, combines App Server, hook, and settlement events, and
publishes the unified dashboard stream. \\
Dashboard &
Displays agents and continuous activity from App Server events alongside risk,
coverage, and settlement details from the insurance path. \\
Facilitator &
Validates the proposed payment, optionally supplies fee abstraction, submits
the transaction group, and reports settlement. \\
Algorand &
Records and finalizes the USDC payment. \\
Tool &
Executes the original existing operation unchanged after the hook allows
it. \\
\bottomrule
\end{tabularx}

\subsubsection{HTTP API}

\begin{tabularx}{\textwidth}{@{}lX@{}}
\toprule
\textbf{Endpoint} & \textbf{Purpose} \\
\midrule
\texttt{POST /evaluate} &
Receives a proposed tool call. It first allows or denies the action and, only
when allowed, returns any required risk assessment and quote. \\
\texttt{POST /coverage/\{quote\_id\}} &
x402-protected endpoint that activates the quoted coverage after payment. \\
\texttt{POST /outcome/\{action\_id\}} &
Records the existing tool's success, failure, or cancellation. \\
\texttt{WS /events} &
Sends an initial dashboard snapshot and then a unified stream of App Server
activity, hook decisions, risk, coverage, settlement, and outcome events. \\
\bottomrule
\end{tabularx}

The backend keeps the current agents, actions, quotes, receipts, outcomes, and
aggregate statistics in memory. When the dashboard connects, the first
WebSocket message is a complete snapshot. The sidebar and all dashboard panels
can therefore render without separate agent or statistics routes. Subsequent
messages contain only incremental updates.

\subsubsection{Data Models}

FastAPI's existing Pydantic integration defines and validates compact backend
models:

\begin{itemize}[leftmargin=*]
  \item \texttt{ToolAction}
  \item \texttt{RiskAssessment} and \texttt{EvaluateResponse}, containing the
  policy decision, risk assessment, and optional quote.
  \item \texttt{CoverageReceipt}
  \item \texttt{ToolOutcome}
  \item \texttt{DashboardEvent}, including the initial snapshot variant.
\end{itemize}

The current dashboard snapshot uses compact action records rather than a
separate agent registration or lookup endpoint.

\section{Alternatives Considered}

\begin{tabularx}{\textwidth}{@{}p{0.24\textwidth}p{0.28\textwidth}X@{}}
\toprule
\textbf{Decision} & \textbf{Alternatives} & \textbf{Selected Approach} \\
\midrule
Agent integration &
Instructions only; custom MCP tools; MCP proxy; Codex hooks. &
Use hooks around selected existing tools, including MCP tools where useful.
Instructions cannot enforce coverage, while custom tools and a proxy add
unnecessary implementation work. \\

Agent monitoring &
Hook events only; CLI JSONL output; polling; Codex App Server. &
Use App Server events because hooks expose only insured calls, while the
dashboard needs continuous multi-agent activity. \\

Insurance timing &
Observe actions after execution; require a separate manual coverage step;
intercept before execution. &
Use \texttt{PreToolUse} so covered calls fail closed until coverage is completed,
followed by \texttt{PostToolUse} for outcomes that can be correlated. Full
automatic hook-side payment is deferred. \\

Risk decision &
Fixed rules; unrestricted model decision; structured model output. &
Use a small model with validated structured output for allow, deny, risk, and
price. The result remains explicit and displayable. \\

Pricing &
Fixed premium; subscription; dynamic per-action premium. &
Use a dynamic premium bound to a server-side quote identifier. This directly
demonstrates Luphra's per-action insurance model. \\

Payment asset &
Native ALGO; TestNet USDC. &
Use TestNet USDC so premiums have a stable, understandable value. \\

Settlement &
Smart contract; ordinary asset transfer through a facilitator. &
Use the facilitator and ordinary transfer. A smart contract does not improve
the core hackathon demonstration. \\

Infrastructure &
Self-hosted facilitator and Algorand node; hosted facilitator and public
TestNet access. &
Use hosted infrastructure to keep the project focused on agent insurance. \\

Dashboard transport &
Separate polling routes for agents, statistics, actions, and settlements; one
WebSocket with a snapshot and incremental events. &
Use \texttt{WS /events}. The initial snapshot renders the complete dashboard;
later messages update it without extra read routes. \\

Dashboard scope &
Chat interface; insurer analytics dashboard; agent control room. &
Use an observational control room: agent list and activity in the center,
agent summary at the top right, and coverage settlements at the bottom right. \\
\bottomrule
\end{tabularx}

\section{Cross-Cutting Concerns}

\subsection{Security}

\begin{itemize}[leftmargin=*]
  \item Never commit private keys or the local \texttt{.env} file.
  \item Use separate payer and receiver TestNet accounts.
  \item Validate that a quote cannot be reused or paid with an altered amount.
  \item Return coverage only after successful verification and settlement.
  \item Keep the TestNet payer key outside hook logs and tool arguments.
  \item Fail closed when the hook cannot obtain a valid coverage receipt.
  \item Treat all facilitator and client payloads as untrusted input.
\end{itemize}

\subsection{Reliability and Error Handling}

The system must distinguish an ordinary payment-required response from failed
pricing, verification, or settlement. The backend exposes the x402-protected
coverage route and receipt state; the current Codex hook fails closed for
covered calls instead of performing an automatic payment-bearing retry.
Duplicate hook invocations and ambiguous settlement outcomes require stronger
idempotency before the design can move beyond a demo.

\subsection{Observability}

The middle dashboard panel displays normalized hook and tool events. The
settlement panel displays the tool name, quote identifier, payer address,
premium, coverage limit, settlement transaction ID, and a LORA link where
available. Private keys, raw reasoning, complete tool arguments, and signed
payloads must never be logged or sent to the browser.
